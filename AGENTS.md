# AGENTS.md

High-signal repo facts for working in this portfolio monorepo. Prefer executable sources (`package.json`, `turbo.json`, `pnpm-workspace.yaml`, app configs) over prose.

## Stack & layout (pnpm workspaces + Turborepo)

- Package manager: `pnpm@12.18.0` (Corepack), Node `>=24.15.0` (`.node-version`). Root scripts run via Turbo (`turbo.json`).
- Workspaces: `apps/*`, `packages/*` (`pnpm-workspace.yaml`). Only `esbuild` may run install scripts.
- `apps/web` (`@portfolio/web`): Nuxt 4 public site, SSR, `fr`/`en` with translated URL prefixes (`nuxt.config.ts` uses `@nuxtjs/i18n` `strategy: 'prefix'` + `customRoutes`; locales in `apps/web/i18n/locales/{fr,en}.json`).
- `apps/api` (`@portfolio/api`): Hono + `@hono/zod-openapi`, Postgres via Drizzle. Vercel entry is `src/index.ts` (default export); local dev server is `src/dev.ts`. Schema/migrations: `src/db/schema/index.ts`, `src/db/migrations` (`drizzle.config.ts`). `/public/*` is CORS-restricted to `ALLOWED_ORIGINS`.
- `packages/design-tokens` (`@portfolio/design-tokens`): `tokens.json` → generated `dist/` (`tokens.css`, `motion`) via custom `node build.mjs`. This is the package that produces build output consumed by others.
- `packages/shared` (`@portfolio/shared`): exports raw TypeScript source (`./src/*.ts`); no build step, `typecheck` is `tsc --noEmit`.
- `apps/admin` (`@portfolio/admin`): Nuxt 4 admin, `ssr: false`, French UI, never indexed, port 3002. Calls the API only through its own `/api/**` proxy (`server/routes/api/[...path].ts`, target `ADMIN_API_ORIGIN`) which adds `ADMIN_PROXY_SECRET` and the client IP; the API refuses `/api/*` without that secret. Auth = Better Auth 1.7 (`apps/api/src/auth`), mounted on `/api/auth/*`; admin routes use `requireSession()` + `requirePermission()` (`apps/api/src/middleware/admin.ts`), rights in `packages/shared/src/permissions.ts`. Built module by module (`docs/admin/09-developpement.md`); nav items with `ready: false` are modules not built yet.
- Content model: one versioned JSON document per item (`content_item` working copy + `content_version` snapshots); schemas in `packages/shared/src/content.ts` (draft validation). The public site must only read published versions. Generic workflow in `apps/api/src/services/workflow.ts` + `content-rules.ts`, exposed via `apps/api/src/routes/admin/content.ts` (`/api/admin/content/*`, RFC 9457, revision guard 409, publish 422); `settings` needs `settings.update` even to read, sensitive publish needs a session younger than 10 min (`requireFreshSession` in `middleware/admin.ts`). Project lifecycle: list / create (`PRJ-NN` never reused, via journal) / order / featured / duplicate / submit (`in_review`) / unpublish / archive / delete (409 if published-not-archived or referenced, 🔐) / diff / preview-token / confirm-field.
- Public site content comes from the API: `GET /public/content` (published versions only, `pending_fields` stripped, `media` map of public copies, `redirects` old→current project slugs, 18 blocks: hero, profile, 7 intros, band, footer, legal, privacy, 5 SEO pages) → `apps/web/server/utils/content.ts` (in-memory cache 60 s with `invalidatePublishedContent()`, stale served if the API is down) → `/api/content` → `plugins/content.ts` (state `published-content`) → composables in `useContent.ts`/`useHomeContent.ts`/`useSite.ts`. Text blocks are bilingual versioned contents (`BLOCK_SCHEMAS` in `packages/shared/src/content.ts`); import idempotent via `pnpm --filter @portfolio/api db:seed:blocks` (legal/privacy as drafts with `[À COMPLÉTER]`). Page SEO blocks drive `usePageSeo` (repli i18n); project `seo` (title/description/share image/index) drives project SEO + sitemap filtering. Publication triggers `POST /api/_revalidate` on the site (`x-revalidate-token` vs `NUXT_REVALIDATE_TOKEN`; API side `SITE_REVALIDATE_URL` + `REVALIDATE_TOKEN`); on Vercel only one instance is emptied, others refresh within 60 s. `/fr/cv` and `/en/cv` are Nitro routes (`server/routes/[locale]/cv.get.ts`) → 302 to the published PDF or 404. `POST /public/contact` (in-memory replaced by Postgres `rate_limit` in module 8) answers 503 `closed` when the published Settings close the form, audits `contact.received` and emails the owner at the published email (never blocking, failures journalised). Inbox: `/api/admin/messages/*` (`services/messages.ts`, `purgeArchivedMessages()` 12 months for module-10 maintenance); viewers see unread count only. Dashboard: `/api/admin/dashboard` + `/api/admin/translations` (`services/dashboard.ts`, `services/translations.ts`, real counts only; module 10 adds probes/alerts/backup + journal chain, `verified` only after a successful restore test). Monitoring: `/api/admin/monitoring/*`, `/api/admin/alerts`, `/api/admin/incidents*`, `/api/admin/backups*` (`services/monitoring.ts`, `services/backup.ts`, `services/maintenance.ts`); internal QStash-signed jobs `POST /internal/checks|backup|maintenance` (`routes/internal.ts`, all 5-min probes/daily backup/maintenance) — in dev trigger with `pnpm --filter @portfolio/api internal -- checks|backup|maintenance`. Private preview: `GET /public/preview/{token}` (HMAC `BETTER_AUTH_SECRET`, 30 min, `services/preview.ts`) renders the working copy on `/fr|en/projets/{slug}?apercu=` with banner, `noindex`, `private, no-store`. **`pnpm dev` (web) now needs the API running and the DB seeded.** Initial content lives in `apps/api/src/seed/` (import only).
- `docs/` records design/architecture decisions: site steps 1–17 in `docs/NN-*.md`, admin steps in `docs/admin/` (spec, workflow, security, data model, build log).

## Commands (run from repo root unless noted)

```bash
pnpm install
pnpm db:up                        # Postgres 17 in Docker (docker-compose.yml; local creds in .env.example)
pnpm dev                          # web dev (turbo, filter @portfolio/web) http://localhost:3000
pnpm dev:api                      # api dev (turbo, filter @portfolio/api) http://localhost:8787 (/health, /openapi.json)
pnpm build                        # turbo build all (dependsOn ^build)
pnpm typecheck                    # turbo typecheck all (dependsOn ^build)
pnpm tokens                       # regenerate design-tokens dist from tokens.json
pnpm --filter @portfolio/api db:generate   # drizzle-kit generate (needs DATABASE_URL env)
pnpm --filter @portfolio/api db:migrate    # drizzle-kit migrate (needs DATABASE_URL env)
pnpm --filter @portfolio/api db:seed       # import the site's current content as published v1 (idempotent; --replace = local wipe)
pnpm --filter @portfolio/api admin:create -- --email you@x.y --name "Name"   # first admin (no public sign-up); password typed hidden
pnpm dev:admin                    # admin dev http://localhost:3002 (needs the API running for /api/**)
```

- `turbo.json`: `dev` and `typecheck` depend on `^build` (design-tokens builds before dependents). `dev` is persistent/non-cached.
- No lint, format, or test scripts are configured in the repo root/apps/packages. Do not invent `pnpm lint`/`pnpm test`; if verification is needed, use `pnpm typecheck` and/or a targeted build.
- Low-memory machines (e.g. WSL ~4 GB): the web and the admin both need the API. Run `pnpm dev:api` plus one front end at a time (`pnpm dev` or `pnpm dev:admin`); for checks, prefer built outputs (`node apps/*/.output/server/index.mjs`).
- `drizzle-kit migrate` prints a Postgres NOTICE (schema "drizzle" already exists) that looks like an error; check the final "migrations applied" line.

## Environment & secrets

- Copy `.env.example` → `.env` (never commit `.env`). Local DB uses Docker values from `docker-compose.yml`; production uses Neon credentials set in Vercel.
- Env loading is per-app: web dev uses `nuxt dev --dotenv ../../.env`; api dev uses `tsx watch --env-file-if-exists=../../.env`; `drizzle.config.ts` reads `process.env.DATABASE_URL` directly.
- Key vars: `DATABASE_URL`, `NUXT_PUBLIC_SITE_URL`, `NUXT_PUBLIC_API_BASE`, `API_PORT`, `ALLOWED_ORIGINS` (comma-separated, used by API CORS for `/public/*`), `NUXT_PUBLIC_SHOW_PLACEHOLDERS` (review mode: `true` locally shows "to provide" media and link placeholders; never set in production. Unconfirmed `pending` fields are never public: they are reviewed in the admin), `ADMIN_API_ORIGIN` (admin: API origin behind the `/api/**` proxy; runtime override `NUXT_API_ORIGIN`), `ADMIN_PROXY_SECRET` (admin + API; admin runtime override `NUXT_ADMIN_PROXY_SECRET`), `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` (= admin origin), `RESEND_API_KEY`/`MAIL_FROM` (empty in dev: emails are printed in the API console), `NUXT_REVALIDATE_TOKEN` (site, shared secret for `_revalidate`), `SITE_REVALIDATE_URL` + `REVALIDATE_TOKEN` (API, same secret), `BACKUP_ENCRYPTION_KEY` (32 bytes base64/hex, AES-256-GCM, keep in password manager too), `CLOUDINARY_CLOUD_NAME`/`CLOUDINARY_API_KEY`/`CLOUDINARY_API_SECRET` (media + backups; raw/PDF delivery must be enabled on the cloud), `QSTASH_CURRENT_SIGNING_KEY`/`QSTASH_NEXT_SIGNING_KEY`/`QSTASH_TOKEN` (Upstash QStash signatures for `POST /internal/*`; dev fallback script `pnpm --filter @portfolio/api internal -- checks|backup|maintenance`), `SENTRY_DSN`/`NUXT_PUBLIC_SENTRY_DSN` (empty in dev: Sentry silent, no IP/PII by design).
- Media: `apps/api/src/services/{storage,media}.ts`. `MEDIA_STORAGE=local` (dev, files in `apps/api/.storage/`, git-ignored, public copies served by `GET /media/*`) or `cloudinary` (prod; driver written but **not yet run against real Cloudinary** — enable PDF/raw delivery on the cloud). Upload = POST `/api/admin/media/uploads` → browser PUTs (local) or posts signed multipart to Cloudinary → POST `…/complete` (real type sniffed, sharp re-encode, EXIF stripped, WebP variants). Files are private until `setMediaPublic(id, true)` (to be called by the publish workflow).
- `audit_log` is append-only (DB trigger). Local cleanup only: `begin; set local app.audit_purge = 'on'; delete …; commit;`. The `user` table refuses removing/demoting the last admin (trigger).

## Conventions & gotchas

- Design values come only from design tokens (`var(--…)` / `@portfolio/design-tokens`); never hard-code colors or motion durations. Edit `packages/design-tokens/tokens.json` and run `pnpm tokens` (or rely on turbo build deps).
- UI copy lives in `apps/web/i18n/locales/{fr,en}.json`; editorial/content data comes from the API. Translated route paths are defined in `nuxt.config.ts` (`i18n.pages`).
- `apps/web` postinstall runs `nuxt prepare`. If types/auto-imports look stale, a prepare/rebuild of deps may be needed (respect `^build` ordering).
- `packages/shared` is consumed as TS source across the monorepo; keep its exports and runtime deps compatible with both Nuxt (web) and Hono (api) consumers.
